How to use this reference

Every symbol a Lua script can reach is listed below by its Lua name and the C++ function that implements it. Classes are userdata object metatables; global tables are ordinary Lua tables created during registration; global values are set with lua_setglobal. Hook callbacks are global functions a script can define to receive engine events.

Quick start — how callbacks work

You never register anything. There is no register_callback, no add_event, no init/setup call. The engine looks for a global Lua function with a fixed name when your script loads. If the function exists, it is called on every matching event; if it does not exist, that hook is simply skipped for your script.

So the whole "API" for hooking is: declare a function with the right name at file scope.

-- my_script.lua  (this is the entire setup)
function on_end_scene()
    -- called every frame, render thread
end

function on_create_move(cmd, player)
    -- called every tick for the local player
end

Names are case-sensitive and use the lowercase on_ form — on_end_scene, not EndScene. The old PascalCase list was only a friendly label; the real global names are in the callback table below. You only return a value for the few callbacks that document one (see the Returns column).

ImGui drawing (on_end_scene) vs engine paint (on_paint)

This is the single most common mistake. There are two unrelated drawing systems and they do not mix:

CallbackUse it forWhat is valid inside
on_end_scene()ImGui. Runs on the render thread once per frame with an active ImGui frame.Everything in the imgui.* table (imgui.begin_window, imgui.text, imgui.button, …).
on_paint()Engine / VGUI / HUD paint.The draw.* helpers (draw.line, draw.rect, draw.string, …).

imgui.* does NOT work inside on_paint. There is no ImGui frame active there, so calls do nothing or break layout. Conversely, draw.* is the engine surface — it is not ImGui and has no widgets. If you want ImGui windows/widgets, use on_end_scene. If you want to draw on the HUD, use on_paint with draw.*.

Every ImGui frame must be balanced with begin/end:

function on_end_scene()
    imgui.begin_window("My window")
    imgui.text("hello")
    if imgui.button("click me") then
        -- true only on the frame the button is pressed
    end
    imgui.end_window()
end

ImGui conventions

The imgui.* functions mirror Dear ImGui's C++ API one-to-one but in snake_case. Their arguments and return values follow the C++ originals, for example:

  • imgui.button(label) → boolean (true on the frame it was clicked)
  • imgui.checkbox(label, value) → value, changed
  • imgui.slider_float(label, value, min, max) → value, changed
  • imgui.input_text(label, text) → text, changed
  • imgui.begin_window(name) / imgui.end_window() → no return

When in doubt, check the Dear ImGui documentation for the matching C++ function — the Lua wrapper keeps the same parameter order and return values.

get_global_vars() — timing / "tick"

There is no bare tick global. get_global_vars() returns a table with named fields. For just the tick or frame time you can also use client.get_tick_count() and client.get_frame_time().

local gv = get_global_vars()            -- returns a TABLE
local tick      = gv.tickcount           -- integer: current tick ("tick")
local curtime   = gv.curtime             -- number
local frametime = gv.frametime           -- number
local interval  = gv.interval_per_tick   -- number: seconds per tick

Object / metatable conventions

Objects passed to callbacks (the cmd userdata, player, materials, textures, weapons, game events) are userdata with a metatable. Their members are called as methods and follow a strict naming rule:

  • get_xxx() returns the value.
  • set_xxx(value) changes it and returns nothing.
  • is_xxx() / has_xxx() return a boolean.
function on_create_move(cmd, player)
    local ang = cmd:get_viewangles()   -- returns a vector
    cmd:set_viewangles(ang)            -- setters return nothing
    local buttons = cmd:get_buttons()
    cmd:set_buttons(buttons)
end
